# 강의 자막 수집 → 데이터 반영

`data/`의 개념·문항은 손으로 쓴다. 이 디렉터리는 그 앞뒤를 받치는 것 두 가지다.

- `merge.py` — 배포 전에 깨진 참조를 잡아내는 무결성 검사기
- `lectures/` — 로컬에서 수집한 강의 자막 요약을 놓는 자리

---

## 왜 원격 세션에서 자막을 못 받았나

Claude Code on the web 컨테이너의 egress 프록시는 허용 목록 방식이라
`youtube.com`과 자막 추출 사이트가 전부 막혀 있다. 확인한 결과는 다음과 같다.

| 대상 | 결과 |
|---|---|
| `youtube.com`, `youtu.be`, `i.ytimg.com` | CONNECT 403 |
| `youtubetotranscript.com`, `youtubetranscript.com`, `tactiq.io` | CONNECT 403 |
| invidious·piped 인스턴스, `r.jina.ai` | CONNECT 403 |
| `github.com`, npm, pypi, `googleapis.com` | 통과 |

그래서 자막 수집은 **네트워크가 열린 로컬 환경**(데스크톱 앱이나 CLI)에서 해야 한다.

---

## 1단계 — 로컬에서 자막 요약 받기

로컬 Claude Code 세션에서 `youtube-playlist-study-notes` 스킬 절차를 따른다. 요점만 적으면:

1. **재생목록에서 영상 ID를 뽑는다.** 브라우저로 재생목록을 열고 콘솔에서

   ```js
   [...new Set([...document.querySelectorAll('a[href*="watch?v="]')]
     .map(a => a.href.match(/v=([\w-]{11})/)?.[1]).filter(Boolean))]
   ```

   제목과 재생시간은 페이지 텍스트로 받아 순서대로 짝지으면 정확하다.

2. **영상마다 자막을 요약으로 받는다.** 자막 원문을 컨텍스트에 넣지 않는 것이 핵심이다.
   영상 1개 자막이 5,000~15,000 토큰이라 40개면 40만 토큰이 넘는다.
   `https://youtubetotranscript.com/transcript?v=<VIDEO_ID>` 에 **WebFetch**를 걸면
   작은 모델이 페이지를 읽고 요약본만 돌려주므로 10~20배 절감된다.

   프롬프트는 산출물 형태를 구체적으로 지정한다. 이 저장소에 맞는 프롬프트:

   > 이 영상 자막에서 한국사 학습 지식만 추출해 한국어로 정리해줘. 인사말·잡담·교재 페이지
   > 안내·수강 안내는 전부 제외. 형식은 "- [항목명]: 설명" 한 줄씩. 왕·사건·제도·문화재는
   > 빠짐없이 나열하고, 연도가 나오면 반드시 함께 적어. 강사가 시험에 나온다고 강조한 부분은
   > [중요] 표시. 헷갈리기 쉽다고 짚어 준 짝(예: A와 B의 차이)은 "[혼동] A ↔ B: 구분점"
   > 형식으로 따로 적어. 촘촘하게 30~60줄. 자막이 없으면 NO TRANSCRIPT만 답해.

   **속도 조절** — 3~4개 연속 요청 후 40~60초 쉰다. 쉬지 않으면 Read timeout이 난다.
   Read timeout은 60초 쉬고 재시도하면 대개 성공한다. 같은 영상에서 400이 반복되면
   그 사이트로는 불가능한 것이니 포기하고 어느 강의가 비었는지 명시한다.

3. **차시별로 파일에 저장한다.** `build/lectures/01.json` 형식으로.

   ```json
   { "lec": 1, "vid": "1Sp3EuDlZgM", "title": "우리는 왜 역사를 공부하는가",
     "lines": ["- [사실로서의 역사]: …", "- [중요] …", "[혼동] A ↔ B: …"] }
   ```

   이 파일은 사이트가 읽지 않는다. 개념을 쓸 때 참고하는 원재료일 뿐이다.

## 2단계 — 개념·문항으로 옮기기

자막 요약을 그대로 싣지 않는다. 강의 표현이 아니라 **역사적 사실**을 정리해 쓴다.
자막은 "어느 항목을 다루는가, 강사가 무엇을 강조했는가, 무엇과 헷갈린다고 했는가"를
알려 주는 참고 자료로만 쓴다.

### 개념 — `data/concepts-<시대>.json`

```json
{"era":3,"src":"lecture","items":[
 {"no":157,"era":3,"lec":14,"type":"인물","imp":3,"yr":"949~975",
  "title":"광종의 개혁",
  "body":[{"type":"text","text":"…","bullet":true},
          {"type":"table","head":["왕","정책"],"rows":[["광종","노비안검법"]]},
          {"type":"steps","items":[{"t":"956","d":"노비안검법"}]},
          {"type":"note","lines":["혼동 주의 — …"]}],
  "keys":["노비안검법","과거제","칭제건원"]}]}
```

분류 축을 네 개 확보하는 것이 이 스키마의 요점이다. 축이 하나뿐이면 검색도 복습도 안 된다.

| 축 | 필드 | 값 |
|---|---|---|
| 시대 | `era` | 1~7 |
| 차시 | `lec` | 1~40 (`index.json`의 `lectures`) |
| 유형 | `type` | 인물 · 사건 · 제도 · 문화 · 사료 · 흐름 |
| 중요도 | `imp` | 3 최빈출 · 2 중요 · 1 참고 |

**중요도는 반드시 3단계로 쓴다.** 2단계로 하면 [중요]가 남발되어 80%가 중요로 표시되고
필터로서 의미가 없어진다. `merge.py`가 3등급 비율이 절반을 넘으면 경고한다.

`body` 블록은 `text`(`bullet` 가능) · `list` · `table` · `steps` · `note` · `quote` 여섯 가지다.

### 문항 — `data/quiz-<시대>.json`

```json
{"era":3,"questions":[
 {"id":"Q-3-014","era":3,"lec":14,
  "stem":[{"type":"text","text":"밑줄 그은 '왕'의 정책으로 옳은 것은?"},
          {"type":"quote","lines":["사료 인용 …"]}],
  "options":[{"no":1,"text":"노비안검법을 실시하였다.","refs":[157]},
             {"no":2,"text":"전민변정도감을 두었다.","refs":[171]}],
  "answer":1,"refs":[157],
  "why":"…"}]}
```

**`options[].refs`가 이 사이트 전체가 딛고 서는 필드다.** 오답 선택지마다
"이 선택지가 실제로 설명하는 개념 번호"를 달아 둔다. 그래야 채점기가

> 광종 문제에서 ②(공민왕의 전민변정도감)를 골랐다
> → "광종을 몰라서"가 아니라 **"광종과 공민왕을 헷갈려서"** 틀렸다

로 기록할 수 있다. 한국사는 오답 선택지가 대부분 "다른 왕·다른 시대의 정책"이므로
이 모델이 특히 잘 맞는다. `refs`를 비워 두면 그 선택지를 골라도 취약 점수가 쌓이지 않는다.

점수 가중치는 `index.html`의 `grade()`에 있다.

| 신호 | 의미 | 가중치 |
|---|---|---|
| 내가 고른 오답의 `refs` | 이 개념을 옳다고 착각했다 | **+3** |
| 정답 선택지의 `refs` | 이 개념을 몰랐다 (부정형 문항은 제외) | +2 |
| 문항 주제 `refs[0]` | 이 주제가 약하다 | +2 |
| 맞힌 문항의 `refs` | 회복 (0 미만으로 내려가지 않음) | −1 |

"잘못 아는 것"이 "모르는 것"보다 위험하므로 +3이 +2보다 크고, 회복(−1)은
한 번 맞혔다고 바로 지워지지 않도록 일부러 느리게 잡았다.

## 3단계 — 검사

개념을 새로 쓴 뒤에는 **반드시** 돌린다.

```bash
python3 build/merge.py            # 검사만
python3 build/merge.py --write    # 검사 후 index.json 의 meta.n 갱신
```

잡아내는 것: 없는 개념을 가리키는 `refs`·`qids`, 개념 번호 중복, 문항 id 중복,
파일과 다른 `era`, 없는 차시, 시대가 어긋난 차시, 알 수 없는 `type`·블록 종류,
선택지 개수와 `answer` 범위, 중복·빈 선택지, 중요도 3등급 쏠림.

오류가 있으면 비0으로 끝나므로 그대로 배포되지 않는다.

## 4단계 — 빠진 것을 숨기지 않는다

자막을 못 받은 차시가 있으면 `index.json`의 해당 `lectures[].src`를 `"seed"`로 둔다.
사이트가 이를 읽어 개념 목록에 「직접 작성」 배지를, 데이터가 아예 없는 시대에는
「수집 대기」를 표시한다. 조용히 빼면 학습자가 다 있는 줄 알고 넘어간다.

자막을 반영한 차시만 `"src": "lecture"`로 바꾼다. `merge.py`는 `lecture`로 표시됐는데
개념이 하나도 없는 차시를 오류로 잡는다.
